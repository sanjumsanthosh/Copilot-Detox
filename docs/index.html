the problem

The muscle you stop using

AI is great at shipping code and quietly terrible for your fundamentals. Reach for completion every time and the part of you that turns a fuzzy problem into a working function atrophies — you find out in an interview, or in an outage, with a blank file and no tab key.

✕ Every other day

Copilot writes it. You skim it. Nobody checks whether you could have. Progress is throughput, not skill.

✓ A detox session

AI sets the exercise, you write it alone, AI grades the result — edge cases, style, and one concrete fix. 15 minutes.

commands

Five verbs, no config files

Everything lives under ~/.copilot-detox/ as plain files — no daemon, no database, no runtime.

CommandWhat it does
detox startGenerates a fresh challenge and opens it in $EDITOR — raw mode
detox submitSends your saved solution to Copilot for review and a score
detox lastSummary of the most recent session
detox last --openRe-open the last solution in your editor
detox last --reviewRead the full review in less
detox statsTotal sessions, completed count, average score, last five
detox clean 30 --yesDelete sessions older than 30 days

under the hood

Plain files, start to score

A question goes in, an attempt snapshot and a review come out. Every submission is kept, so attempt 3 sits next to attempt 1.

detox start
  │
  ├─ gh copilot suggest  →  question.md
  ├─ starter code       →  solution.py
  └─ $EDITOR opens… no AI in sight

detox submit
  │
  ├─ solution + question  →  gh copilot suggest
  └─ attempt_N.py + attempt_N_review.md + score
~/.copilot-detox/
├── last_session
└── sessions/
    └── 2026-11-15T14-30-00/
        ├── question.md          challenge
        ├── solution.py          your working file
        ├── meta.json            attempts, status, score
        ├── attempt_1.py         snapshot per submit
        └── attempt_1_review.md  the full review

requirements

What you need

  • Bash 4.0+ and GNU coreutils (Linux, WSL)
  • GitHub CLI with the gh copilot extension
  • An active Copilot subscription
  • Any editor — nvim, vim, nano, or $EDITOR

Heads up on macOS

macOS ships Bash 3.2 and BSD grep/sed/date, so a handful of commands need portability fixes. Linux and WSL are the tested path; the port is on the roadmap.
